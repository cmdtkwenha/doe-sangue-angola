# Production Deployment

This checklist prepares Doe Sangue Angola for a real production deploy.

## Production Goal

Production should run the web platform on Vercel, the donor app through Expo
EAS, and Supabase as the managed backend.

Keep the first public deploy conservative:

- Web deploys from GitHub to Vercel.
- Mobile builds are generated by EAS.
- Supabase stores auth, requests, appointments, notifications, rewards and
  audit logs.
- Push notifications fail safely if Expo push is unavailable.

## Required Accounts

- GitHub repository access.
- Vercel team or personal account.
- Supabase project.
- Expo account with EAS enabled.
- Domain owner access for DNS.

## Environment Modes

Use these modes:

| Mode | Purpose |
| --- | --- |
| `development` | Local work on a laptop. |
| `staging` | Private testing with safe data. |
| `production` | Public launch. |

Production variables start from `.env.production.example`.

## Supabase Production Setup

1. Create a new Supabase project for production.
2. Run `supabase/migrations/001_initial_schema.sql`.
3. Run `supabase/migrations/002_push_notifications.sql`.
4. Load `supabase/seed/seed_data.sql` only if demo records are approved.
5. Review RLS policies with the technical owner.
6. Copy the project URL and anon key into Vercel and EAS.
7. Store `SUPABASE_SERVICE_ROLE_KEY` only in Vercel server variables.

Never place the service role key in Expo variables.

## Vercel Production Setup

Follow [Vercel Production](./vercel-production.md).

Minimum production variables:

```bash
NEXT_PUBLIC_APP_ENV=production
NEXT_PUBLIC_AUTH_MODE=supabase
NEXT_PUBLIC_DATA_MODE=supabase
NEXT_PUBLIC_PUSH_MODE=expo
NEXT_PUBLIC_SITE_URL=https://doesangue.ao
NEXT_PUBLIC_API_URL=https://doesangue.ao
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
```

## Final Checklist

- `npm install` runs cleanly.
- `npm run check:lines` passes.
- `npm run lint` passes.
- `npm run test` passes.
- `npm run typecheck` passes.
- `npm run build` passes.
- Vercel preview opens `/auth`, `/admin`, `/hospital` and `/mobile`.
- Supabase auth roles redirect correctly.
- Hospital request creates a database row.
- Donor acceptance creates an appointment and PIN.
- PIN validation updates the database.
- Completion adds reward points and audit logs.
- Expo development build opens without Expo Go.
- Android preview build installs on a real device.

## Rollback Plan

If production data has issues, set these variables and redeploy:

```bash
NEXT_PUBLIC_DATA_MODE=mock
NEXT_PUBLIC_PUSH_MODE=mock
EXPO_PUBLIC_DATA_MODE=mock
EXPO_PUBLIC_PUSH_MODE=mock
```

This keeps the product presentable while backend issues are corrected.
